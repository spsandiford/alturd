<objective>
Close the one literal must-have failure recorded in 04-VERIFICATION.md (the difftool title
bar truncates without appending an ellipsis) and, per the developer's explicit disposition of
04-VERIFICATION.md's CR-01/CR-02 human-verification item, fix the two Critical findings from
04-REVIEW.md in the same pass.

Purpose: 04-VERIFICATION.md scored the phase 43/45 with exactly one FAILED truth — the
ellipsis. The root cause is that `lipgloss.Style.MaxWidth()` calls `ansi.Truncate(line, maxWidth, "")`
internally with a hardcoded empty tail, so 04-03-PLAN.md's premise about the mechanism was
simply wrong; the title bar truncates and stays a single row (truth #13, VERIFIED) but emits no
ellipsis, contradicting 04-UI-SPEC.md's DIFFTOOL-02 Copywriting Contract ("ellipsis appended",
lines 212-214 and 273). The verifier separately routed 04-REVIEW.md's CR-01 (a reproducible
`View()` panic on degenerate terminal heights) and CR-02 (the abort key skipping bubbletea's
terminal restore) to the developer as a product call rather than an automatic gap; the developer
chose to fix both now. Both are reachable through the interactive surface this phase ships:
CR-02 fires on the same `Q` binding in difftool mode, and CR-01 lives in the standalone render
path this phase's config/theme code gates into.

All three fixes land in one plan because all three touch `internal/tui/model.go` — splitting
them across parallel plans would create a guaranteed file conflict for zero benefit.

Output: an ellipsis-appending title bar, a panic-free render path at any terminal height, and an
abort that returns the terminal to the user intact while preserving exit status 1.

**No tracer task.** TRACER_MODE is on, but this plan adds no new capability and crosses no new
layers — it is three surgical corrections inside code paths that already run end-to-end and are
already covered by a green test suite. A synthetic vertical slice here would be ceremony, not
information. Each task is instead TDD-shaped: the failing test that reproduces the defect is
written first, which is the strongest available proof that the gap was real and is now closed.

**Explicit scope decision — the tree pane is NOT changed.** `renderTree()` (around line 420 of
`internal/tui/model.go`) uses the identical no-ellipsis `lipgloss...MaxWidth(m.treeWidth).Render(line)`
pattern, and 03-UI-SPEC.md D-04 also says "ellipsis appended at end when truncated", so the tree
pane has the same latent spec violation. It stays untouched here for three reasons: (1) it is a
Phase 3 contract governed by a Phase 3 spec, not a Phase 4 requirement — 04-UI-SPEC.md scopes the
ellipsis rule to the DIFFTOOL-02 title bar only, and 04-VERIFICATION.md's gap names only the
title bar; (2) the selected tree row is re-rendered through `lipgloss...Reverse(true)`, so
changing the truncated width by a glyph changes the highlight geometry and risks regressing
Phase 3 tree tests that this gap-closure pass has no mandate to touch; (3) fixing it silently
would hide a real Phase 3 defect inside a Phase 4 commit. It is recorded below as tracked debt.

**Explicitly out of scope** (left as tracked debt, deliberately not fixed here, per the
developer's scope decision): 04-REVIEW.md WR-01 (`refreshTreeContent` sets the wrong viewport's
width), WR-02 (`diffW` unclamped on narrow terminals — the *width* twin of CR-01; this plan
