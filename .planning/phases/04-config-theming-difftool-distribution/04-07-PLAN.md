<objective>
Close UAT gap G-04-1: pressing the abort key inside a `git difftool -t alturd` session prints
`fatal: external diff died, stopping at <file>` and the session exits 128 instead of returning
cleanly.

The root cause is fully diagnosed (see `.planning/debug/DEBUG-difftool-trustexitcode-fatal.md`):
`install-difftool` writes `difftool.trustExitCode = true`, which makes git forward alturd's
intentional abort exit code into git's diff engine — and that engine treats *any* non-zero exit
from an external diff command as an unconditional fatal crash. There is no git-side way to say
"the user cancelled, stop quietly".

Purpose: make the difftool session exit cleanly on abort, and leave the codebase's own comments
telling the truth about why alturd still exits 1.
Output: a difftool install whose trust setting is pinned off, an automated end-to-end regression
test that reproduces the exact failure mode, and a corrected UAT expectation.
</objective>

    anything about `--scope`/`--name`/`--force` handling.

    Write the opposite boolean explicitly rather than unsetting the key. This was verified empirically
    against the installed git 2.39.5: git resolves this key across the system then global then local
    precedence chain, so if `install-difftool --scope global` merely removed the key, a lower-precedence
    scope still holding the superseded value would win and the fatal would come straight back. An
    explicit value at the install scope overrides everything below it, and it also converges any machine
    that already ran the previous version of `install-difftool` — which is what D-10's "the command
    converges the config" means. `git-difftool--helper` forwards the backend's exit status only when the
    resolved value is exactly the string `true`, so the new value restores git's masking behaviour.

    Update the comment prose in the same file so it no longer states the superseded rationale. Three
    places reference it: the package-level header block at the top of the file, the `D-08:` comment
    immediately above the four `gitConfigSet` calls, and `runInstallDifftool`'s own doc comment. The
    corrected rationale to record, citing gap `G-04-1` and
    `.planning/debug/DEBUG-difftool-trustexitcode-fatal.md`: git's external-diff protocol has exactly
    two outcomes for the invoked command's exit status — zero means success, and every non-zero value is
    an unconditional fatal crash. It cannot represent "the user intentionally cancelled", so a trusted
    non-zero exit can never produce the clean stop D-08 assumed it would. Also record the trade-off the
    user accepted: in a multi-file `git difftool` session with no pathspec, aborting on file N no longer
    prevents file N+1 from opening — git walks every remaining changed file. Keep the existing
