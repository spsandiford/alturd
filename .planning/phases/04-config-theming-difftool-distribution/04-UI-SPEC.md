# Phase 4 — UI Design Contract

> Visual and interaction contract for the TUI (terminal user interface) surface of Phase 4.
> This is a Go terminal application. Design contracts are expressed in terminal cells and
> ANSI color codes, not CSS pixels or web components.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 4 is primarily non-visual (TOML config parsing, OSC 11 timeout wrapping,
gitconfig writes, CI/goreleaser). This contract covers only the surfaces that render on screen
or print user-facing text: (1) theme *resolution* consuming Phase 3's existing dark/light
palette, (2) the difftool single-file mode's reduced-chrome layout and title bar, and
(3) CLI-level copy for config validation errors and `install-difftool` output. DIST-01/02/03
(CI, goreleaser, binary distribution) have zero on-screen presentation and are explicitly
out of scope for this document — see REQUIREMENTS.md §Distribution for their acceptance
criteria instead.

## Color — Theme Resolution (THEME-01)

No new color values are introduced. Phase 4 adds a **resolution layer** that decides which of
the two already-existing palettes (`darkBg = true` → monokai/bright-marker set, `darkBg = false`
→ github/dark-marker set) is active. The palettes themselves are unchanged from Phase 3.

### Precedence (D-05, D-07)

```
1. --theme flag        (explicit "light" | "dark" — "auto" behaves as if unset)
2. config `theme` key   (TOML: theme = "light" | "dark" | "auto")
3. auto-detect          (OSC 11 via termenv, 50ms external timeout — standalone mode only)
4. dark fallback        (always wins if 1-3 are unset/inconclusive)
```

| Mode | OSC 11 query attempted? | Source |
|------|--------------------------|--------|
| Standalone (interactive TUI, no `--difftool-*` flags) | Yes, race against 50ms `time.After` | D-05, 04-RESEARCH.md Pattern 3 |
| Difftool (any `--difftool-*` flag set) | **No — skipped unconditionally** | D-06 |

In difftool mode, unresolved theme (no `--theme`, no config `theme` key) always resolves to
**dark fallback** — the same terminal-round-trip risk documented in
`.planning/research/PITFALLS.md` Pitfall 10 applies to git's difftool subprocess environment,
so the query must never be attempted there, not merely time-boxed.

### Reused Palette Reference (unchanged values, for completeness)

| Role | Dark (`darkBg=true`) | Light (`darkBg=false`) |
|------|----------------------|--------------------------|
| Syntax highlighting (Chroma style) | `monokai` | `github` |
| `[A]` marker | ANSI 82 (bright green) | ANSI 28 (dark green) |
| `[D]` marker | ANSI 203 (bright red) | ANSI 88 (dark red) |
| `[M]` marker | ANSI 220 (bright yellow) | ANSI 136 (dark amber) |
| `[R]`/`[C]` marker | ANSI 81 (bright cyan) | ANSI 26 (dark blue) |
| `[B]`/`[S]`/unknown marker | ANSI 245 (medium gray) | ANSI 240 (dark gray) |
| Diff line backgrounds (added/removed/modified) | ANSI 22 / 52 / 58 (unaffected by theme) | ANSI 22 / 52 / 58 (unaffected by theme) |

Diff line background colors are **not** theme-conditional — they were fixed in Phase 1/3 and
Phase 4 does not touch them.

### 60/30/10 Mapping

## Layout — Difftool Mode Geometry (DIFFTOOL-01, DIFFTOOL-02)

Difftool mode is a **reduced-chrome variant** of the standalone layout: no file tree pane, no
pane separator, no `Tab`/`a` affordances. The diff pane's own side-by-side (old/new column)
rendering — established in Phase 1 — is unchanged; "side-by-side" in DIFFTOOL-01 refers to
that column layout, not to tree+diff split.

### Pane Widths (difftool mode)

| Pane | Width | Notes |
|------|-------|-------|
| Tree pane | **absent** | Not constructed; no `treeVP` in difftool mode |
| Separator | **absent** | No `│` column-separator glyph rendered |
| Diff pane | `termWidth` (full width) | No `treeWidth`/separator subtraction |

### Row Heights (difftool mode)

Identical formula to standalone mode — only the width side changes:

```
contentH = termHeight - 1             // status bar always reserved
if searchMode { contentH -= 1 }       // search bar, same as standalone (D-13)

diffVP.SetWidth(termWidth)            // full width — no treeWidth subtraction
diffVP.SetHeight(contentH)
```

### Interaction States (difftool mode)

| Key | Behavior in difftool mode | Rationale |
|-----|----------------------------|-----------|
| `n` / `N` | Hunk navigation — same centering formula as standalone | NAV-01 unchanged |
| `v` | Toggle full-file/hunk-only render mode | DIFF-06 unchanged |
| `/` | Open in-pane search; `Esc` closes | SEARCH-01 unchanged |
| `q` | Quit, exit 0 | NAV-04 unchanged |
| `Q` | Abort, exit 1 — this is the exit code `difftool.trustExitCode` reads to signal git to stop iterating remaining files (D-08) | NAV-04, D-08 |
| `]` / `[` | Wired but **visibly inert** — difftool mode constructs exactly one `gitdiff.File` in the model, so `(currentFile ± 1) % 1` always resolves to the same file. No special-case skip required in code; this is a natural consequence of `len(files) == 1`. | DIFFTOOL-01 |
| `Tab` | **No-op** — no tree pane exists to focus; must not attempt to resize a nonexistent `treeVP` | DIFFTOOL-01 |
| `a` | **No-op** — no tree pane exists to toggle between changed-files/full-repo view | DIFFTOOL-01 |

The model needs a `difftoolMode bool` (or equivalent) threaded through construction so `Tab`
and `a` can be short-circuited before any tree-viewport code path executes — this prevents a
nil-pointer/zero-value viewport resize rather than merely being a cosmetic restriction.

## Copywriting Contract

### Difftool Title Bar (DIFFTOOL-02)

Replaces the standalone status bar format (`03-UI-SPEC.md`'s
`alturd — {filename} (N of M changed files)`) entirely in difftool mode — these are two
distinct templates, not one appended to the other.

| Template | Condition |
|----------|-----------|
| `alturd (difftool) — {N} of {M} — {filename}` | `GIT_DIFF_PATH_COUNTER`/`GIT_DIFF_PATH_TOTAL` both present |
| `alturd (difftool) — {filename}` | Either env var absent (e.g. manual `--difftool-local/-remote/-path` invocation not spawned by `git difftool`) |
| `alturd (difftool) — {N} of {M} — {filename} [SEARCH]` | Search open, counters present |

- `{N}` = `GIT_DIFF_PATH_COUNTER` (1-based, set by git; read once at startup)
- `{M}` = `GIT_DIFF_PATH_TOTAL` (set by git; read once at startup)
- `{filename}` = `filepath.Base(mergedPath)` where `mergedPath` is the value passed via
  `--difftool-path` (git's `$MERGED`) — per 04-RESEARCH.md Pattern 4
- Padded to `termWidth` via the same `lipgloss.NewStyle().Width(termWidth).Render(...)` pattern
  as the standalone status bar (03-UI-SPEC.md D-05)
- Long filename overflow: truncate with `lipgloss.Style.MaxWidth(termWidth - {fixed prefix
  length}).Render(filename)`, ellipsis appended — same truncation *mechanism* as the tree pane
  filename truncation (03-UI-SPEC.md D-04), applied here to the title bar instead of a tree row

| Example | Condition |
|---------|-----------|
| `alturd (difftool) — 3 of 7 — render.go` | Normal invocation via `git difftool -t alturd` |
| `alturd (difftool) — 3 of 7 — render.go [SEARCH]` | Search open |
| `alturd (difftool) — render.go` | Manual invocation, no `GIT_DIFF_PATH_COUNTER`/`TOTAL` set |

### Config Validation Errors (CONFIG-01, CONFIG-02)

All config errors are single-line, printed to stderr, prefixed `config:`, and cause startup to
abort before any TUI code runs (D-02). Follows the existing single-line error convention already
established by `internal/git.ExecRunner` (GIT-05).

| Situation | Error Copy | Source |
|-----------|------------|--------|
| Unknown TOML field | `config: unknown field "{field}" in {path}` | D-02; 04-RESEARCH.md Pattern 1 (`toml.StrictMissingError`) |
| Invalid `theme` value | `config: invalid theme "{value}" (must be "light", "dark", or "auto")` | D-05 |
| Unrecognized key string for a known action | `config: unrecognized key "{key}" for action "{action}"` | D-02 |
| Unknown action name in `[keybindings]` | `config: unknown keybinding action "{action}"` | D-02 |
| Duplicate/conflicting key bound to two actions | `config: key "{key}" is bound to both "{action1}" and "{action2}"` | D-02; 04-RESEARCH.md Open Question 2 |
| Config file unreadable (permissions, malformed TOML syntax) | `config: {underlying error}` (wrapped, not swallowed) | D-02 |

No config error ever produces a multi-line stack trace or a raw library error dump — every
branch wraps into one of the templates above (or an equivalent single-line `fmt.Errorf` wrap).

### `install-difftool` CLI Output (DIFFTOOL-03)

Not a TUI surface — no bubbletea program runs for this subcommand. Plain stdout/stderr text
only. Treated here as a copy contract because it is user-facing and phase-scoped.

| Situation | Copy | Stream | Exit Code |
|-----------|------|--------|-----------|
| First install (no prior `diff.tool` set) | `Installed alturd as git difftool "{name}" (scope: {scope}).` | stdout | 0 |
| Idempotent re-run (own keys already set — D-10) | `alturd is already configured as git difftool "{name}" (scope: {scope}).` | stdout | 0 |
| `--force` overwrite of a different existing tool | `Overwrote existing diff.tool "{old}" with "{name}" (scope: {scope}, --force).` | stdout | 0 |
| Existing `diff.tool` set to something else, no `--force` (D-10) | `diff.tool is already set to "{old}"; pass --force to overwrite.` | stderr | 1 |
| `--scope local` run outside a git repository (Pitfall D) | `--scope local requires running inside a git repository.` | stderr | 1 |

### Destructive Actions

| Action | Confirmation Approach | Source |
|--------|------------------------|--------|
| `install-difftool` overwriting an existing, different `diff.tool` value | No interactive prompt (this is a CLI, not the TUI) — the explicit `--force` flag itself IS the confirmation mechanism; omitting it blocks with the error above | D-10 |
| `Q` abort (existing, unchanged) | No confirmation — immediate `os.Exit(1)`, matches Python implementation parity (03-UI-SPEC.md) | NAV-04 |

No new confirmation-dialog UI is introduced in Phase 4 — both destructive paths use existing
CLI/TUI conventions (explicit flag, or immediate keypress) rather than a modal.

Categories not raised (dismissed, no UI element of the applicable kind exists this phase):
`loading` — no async operation is introduced in Phase 4 (config load, theme detection, and
gitconfig writes are all synchronous, consistent with the project's existing sync-only pattern);
`zero-one-many` — difftool mode is definitionally single-file, so a one/many distinction does
not apply within a single model instance (the "many files" concept lives at the shell-loop level
across separate `git difftool` process spawns, outside this TUI's rendering responsibility);
`long-text` — covered by the `overflow` row above (same truncation mechanism, not a separate
concern for this phase's new surfaces).
