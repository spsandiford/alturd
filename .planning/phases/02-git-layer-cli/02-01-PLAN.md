    - Test "paths_only": args=["internal/"], dashIdx=0 → ["--","internal/"]
    - Test "ref_plus_paths": args=["HEAD~1","internal/"], dashIdx=1 → ["HEAD~1","--","internal/"]
  </behavior>
  <action>
    Create `internal/git/args.go` in package `git` with the exported pure function `ParseRefArgs(args []string, dashIdx int) []string`. `dashIdx` is cobra's `cmd.ArgsLenAtDash()` — the split index where the path-separator appeared in the raw args, or -1 when absent.

    Logic: when `dashIdx >= 0`, split `refs = args[:dashIdx]` and `paths = args[dashIdx:]`; otherwise `refs = args` and `paths` is empty. Build the result slice from refs as-is (alturd is a pass-through — git itself validates ref syntax and resolves the two-dot/three-dot/two-arg semantic difference, so do not parse or rewrite ref strings). When `len(paths) > 0`, append the path-separator token (two hyphens) followed by the path elements. This re-insertion is mandatory because cobra strips the separator from its args slice (per Pitfall 2) — without it `git diff HEAD internal/` would treat `internal/` as a ref instead of a path filter.

    The returned slice is the args that the caller prepends "diff" to before passing to Runner.Run. ParseRefArgs itself does NOT add "diff".

    Document in the function doc comment that ParseRefArgs is a verbatim pass-through of ref tokens and that the caller prepends the diff subcommand.

    In args_test.go (package `git_test`): write `TestParseRefArgs` with the seven table cases above using `slices.Equal` for comparison and snake_case subtest names via t.Run.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args → git subprocess | User-supplied ref/path strings cross into exec.Command |
| git subprocess → diff parser | Untrusted subprocess stdout/stderr crosses back into the process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | ExecRunner.Run subprocess invocation | high | mitigate | Use `exec.Command("git", args...)` argv form; never `sh -c` string concatenation — each ref/path is a distinct argv element, no shell injection surface regardless of characters (ASVS V5) |
| T-02-02 | Tampering | ParseRefArgs path-filter handling | medium | mitigate | Path args passed verbatim to git via argv after the `--` separator; git's own path validation applies; alturd performs no shell interpolation |
| T-02-03 | Information Disclosure | ExecRunner error mapping | low | mitigate | Failures map to fixed single-line sentinel messages (ErrGitNotFound/ErrNotGitRepo); raw git stderr is never echoed to the user verbatim |
| T-02-SC | Tampering | Go module dependencies | low | accept | No new external modules added in this plan (stdlib only: os/exec, bytes, errors, io, fmt); RESEARCH.md Package Legitimacy Audit verdicts all OK via proxy.golang.org |
</threat_model>
