    Create `internal/log/log.go` with package name `applog` (the import path is internal/log but the package identifier is applog, per PATTERNS.md §Pattern 5). Define `const maxLogSize = 1 << 20` (1 MB).

    Implement `func Init() (*os.File, error)`:
    - Resolve the path via `xdg.StateFile("alturd/alturd.log")`; return the wrapped error on failure.
    - `os.Stat` the path; if it exists AND `fi.Size() > maxLogSize`, call `truncateLog(path)`.
    - Open with `os.OpenFile(path, os.O_CREATE|os.O_APPEND|os.O_WRONLY, 0600)` (mode 0600 — owner-only).
    - Redirect charmbracelet/log output to the opened file.
    - Return the open `*os.File` (so the caller defers Close) and nil.

    Implement `func truncateLog(path string) error` that keeps the LAST maxLogSize bytes: read the whole file, and when its length exceeds maxLogSize, slice the trailing maxLogSize bytes, then write back with mode 0600. Do NOT use `os.Truncate(path, maxLogSize)` — that retains the head and drops recent entries (per Anti-Patterns).

    Wrap all returned errors with `fmt.Errorf("...: %w", err)` per the project's %w idiom.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| XDG_STATE_HOME env → log file path | Process-owner-controlled env var influences the log file location |
| process logs → on-disk file | Structured log content written to a persistent file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Elevation of Privilege | xdg.StateFile log-path resolution | low | accept | xdg.StateFile returns a path under the process owner's own state dir; an attacker who controls XDG_STATE_HOME already runs as that user and can only affect files they own — no privilege boundary crossed |
| T-02-05 | Information Disclosure | log file permissions | low | mitigate | Log opened and written with mode 0600 (owner read/write only) so other local users cannot read potentially path-bearing log content |
| T-02-06 | Denial of Service | unbounded log growth | low | mitigate | 1 MB tail-truncation cap enforced on every Init (startup) prevents the log file from growing without bound |
| T-02-SC | Tampering | adrg/xdg + charmbracelet/log dependencies | low | accept | Both pinned to audited versions (xdg v0.5.3, charmbracelet/log v1.0.0); RESEARCH.md Package Legitimacy Audit verdicts OK via proxy.golang.org; both listed as project-selected in CLAUDE.md |
