# Phase 04.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| git → alturd (difftool argv) | `git difftool` supplies `$LOCAL`, `$REMOTE`, `$MERGED` as CLI arguments; `loadDifftoolFiles` reads two of those paths from disk. | File paths (argv), file content (read-only) |
| repository → CI | `.golangci.yml` is consumed by the GitHub Actions `lint` job; a config change alters what CI enforces on every future push. | Lint configuration |
| filesystem → process memory | `os.ReadFile` loads a whole git temp file into memory for full-file rendering. | Working-tree/temp file content |
| planning record → human reader | `REQUIREMENTS.md` and `04-VALIDATION.md` are artifacts a future reader, auditor, or milestone-archival step trusts to describe what is verified. | Traceability/status records |
| validate-phase workflow → repository | The `gsd-validate-phase` skill runs with write access to the repo; intended blast radius is one VALIDATION.md. | Planning document writes |
| repository → user's terminal | The user builds and runs `alturd` from this working tree in their own interactive shell, against a git repo of their choosing. | Compiled binary execution |
| alturd → user's git repo | The TUI shells out to git (`git diff`, `git ls-tree`) and reads working-tree file content for display. | Diff/file content |
| human report → planning record | The user's spoken pass/fail becomes the durable verification record for nine v1 requirements. | UAT verdicts |
