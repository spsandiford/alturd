Execute the blocking human verification checkpoint that Phase 3 defined but never ran, and record the result. `03-05-PLAN.md` Task 3 is a `checkpoint:human-verify` with a 10-step checklist; `03-VERIFICATION.md` flagged it as *"blocking — required to confirm the binary actually launches and navigates correctly in a real terminal"*. Purpose: `v1.0-MILESTONE-AUDIT.md` calls this *"the one item worth closing before calling the milestone fully done, since it's the core user-facing experience the whole port exists to deliver."* Every Phase 3 requirement has passing unit tests proving dispatch logic, but no test in the suite can prove the alternate-screen TUI renders correctly, that panes lay out at the right widths, or that a status marker is coloured rather than plain text.

Output: `04.1-UAT.md`, recording an executed session against the real binary.

**Why this is a live human session and not automation (D-02).** `04-UAT.md`'s difftool test was verified by scripted pty automation, and that was correct for what it asserted. It is the wrong instrument here: pty capture cannot confirm colour rendering, and colour rendering (TREE-01) is exactly one of the two unverified items. The user runs the binary in their own terminal, at their own colour profile, and reports back.

**Why this plan waits on 04.1-01.** So the session runs against the final v1.0 code. `04.1-01`'s WR-07 fix touches difftool mode only and is semantically neutral for the standalone TUI path exercised here, and its gofmt/lint work changes no behaviour at all — but a recorded UAT pass should name a binary built from the tree as it will ship, not an intermediate one. This costs minutes and removes any question about which build was tested.

**Requirement IDs.** Phase 04.1 has no requirement IDs of its own (ROADMAP shows `Requirements: TBD`). The 9 IDs above are the Phase 3 requirements this session exercises; they are already `[x]` satisfied with passing automated tests. This plan supplies the human-observable confirmation their verification record was missing — it does not newly satisfy them.
