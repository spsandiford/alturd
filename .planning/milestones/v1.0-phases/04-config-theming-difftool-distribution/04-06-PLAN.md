<objective>
Close G-04-2: `git difftool -t alturd <file>` recursively re-enters git's own difftool dispatch
instead of launching the alturd TUI, spawning processes until `fork()` fails.

Purpose: this is the phase's one remaining UAT blocker. `.planning/debug/difftool-recursive-diff-loop.md`
confirmed the root cause empirically — git's difftool builtin unconditionally sets
`GIT_EXTERNAL_DIFF=git-difftool--helper` in the environment of whatever it invokes as
`difftool.<name>.cmd`, and `difftoolDiff`'s `exec.Command("git", "diff", "--no-index", ...)`
inherits that environment without overriding it and without `--no-ext-diff`. So alturd's internal
"diff two temp files" primitive does not compute a diff at all: it delegates back to
`git-difftool--helper`, which re-dispatches to `difftool.alturd.cmd` = alturd with fresh
`$LOCAL/$REMOTE/$MERGED`, which calls `difftoolDiff` again — unbounded. The debug session's
experiment C proved `--no-ext-diff` suppresses the dispatch while preserving the 0/1 exit-code
contract `difftoolDiff` already relies on. That single flag is the gap's stated remediation and is
Task 1.

Task 2 is a deliberate, scoped extension of the same root-cause family, grounded in the debug
session's own call-site audit (Evidence 2026-08-05T00:17:00Z, which enumerated all three
`exec.Command` sites in the repo). `difftoolDiff` is the only site that can *recurse*, but it is
not the only site that can be *hijacked*: the standalone `alturd [ref]` path composes
`{"diff", ...refs}` and hands it to `ExecRunner.Run`, so a developer who has `diff.external`
pointed at delta or difftastic — an entirely normal configuration for this product's audience —
currently has that renderer's output fed into `diff.Parse` instead of a unified diff. Same cause
(alturd's diff-computation primitive is not immune to external-diff configuration), same one-flag
fix, one extra test. Both tasks edit `cmd/alturd/main.go`, so they must share a plan; splitting
them would manufacture a file conflict for no benefit.

Explicitly NOT in scope: overriding `cmd.Env` to strip `GIT_EXTERNAL_DIFF` (the flag already
covers both the environment and the config source, and rebuilding the child environment risks
dropping variables git needs); hardening against other diff-output-shaping config such as
`diff.noprefix` or `color.diff = always`; and any change to `internal/git/runner.go`, whose
documented contract is that the caller composes argv.

Output: an alturd that computes its own diffs no matter what external-diff configuration it is
invoked under, plus an automated regression gate that fails loudly if the flag is ever dropped.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git (parent process) → alturd | When alturd runs as `difftool.<name>.cmd`, git's difftool builtin populates the child environment, including `GIT_EXTERNAL_DIFF=git-difftool--helper`. alturd controls none of it and must not depend on its absence. |
| user gitconfig → alturd's git subprocess | `diff.external` (global, system, or repo `.git/config`) redirects what any `git diff` alturd runs actually executes. |
| alturd → OS process table | Every `difftoolDiff` call spawns a git subprocess; a self-referential dispatch turns one invocation into unbounded process creation. |
| difftool temp files → alturd | `$LOCAL`/`$REMOTE` paths arrive as flag values and cross into an `exec.Command` argv. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06-01 | Denial of Service | `difftoolDiff`'s git subprocess inheriting `GIT_EXTERNAL_DIFF` (`cmd/alturd/main.go`) | critical | mitigate | This is G-04-2 as observed: the diff primitive re-enters git's difftool dispatch, which re-invokes alturd, until `fork()` fails and the user's machine runs out of processes — an availability failure inflicted on the whole session, not just on alturd. Task 1 adds `--no-ext-diff` so the primitive can never dispatch outward, removing the cycle rather than bounding it. `TestDifftoolDiffIgnoresExternalDiffConfiguration` fails if the flag is dropped. |
| T-04-06-02 | Tampering | Program named by `GIT_EXTERNAL_DIFF` or `diff.external` executed by alturd's own subprocess | medium | mitigate | Pre-fix, alturd executes whatever program the ambient external-diff configuration names, with `$LOCAL`/`$REMOTE` temp-file paths as arguments, on every difftool invocation. That program is not necessarily one the user intended alturd to run (a stale `diff.external` in a cloned repo's `.git/config`, for example). Task 1 stops alturd from executing it at all; Task 2 does the same for the standalone path. Severity is medium rather than high because git itself, not alturd, is the usual executor of that setting and the value is not attacker-supplied over a network. |
| T-04-06-03 | Tampering | Standalone `git diff` output shaped by `diff.external` before reaching `diff.Parse` (`cmd/alturd/main.go`) | medium | mitigate | A delta/difftastic user currently has a third-party renderer's output parsed as if it were a unified diff, producing silently wrong or empty rendering with no error. Task 2's `diffArgs` pins the standalone argv to git's own diff output. |
| T-04-06-04 | Denial of Service | Absence of an explicit recursion-depth guard in alturd | low | accept | No depth counter or re-entrancy sentinel is added. With the dispatch vector removed at its only reachable call site (the debug session's 00:17 call-site audit confirmed `difftoolDiff` is the only `exec.Command` reachable from inside a difftool subprocess tree), a depth guard would defend against a cycle that no longer exists while adding state that could itself misfire on legitimate nested invocations. |
| T-04-06-05 | Information Disclosure | git's stderr surfaced verbatim through `difftoolDiff`'s error wrapping | low | accept | Unchanged by this plan: the existing `git diff --no-index: %s` wrapping already prints git's own message, which is the desired behaviour for a CLI and contains only paths the user supplied. |
| T-04-06-SC | Tampering | Third-party dependency supply chain | low | accept | No package-manager install occurs. This plan adds no module, runs no `go get`, and performs no `go mod tidy` upgrade; the only new imports are standard library (`io`, `os`, `os/exec`, `path/filepath`, `runtime`, `strings`, `testing`, and optionally `slices`). The package-legitimacy checkpoint protocol therefore does not apply. |
