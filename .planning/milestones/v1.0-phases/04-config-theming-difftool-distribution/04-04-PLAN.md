<objective>
Add the `install-difftool` subcommand that registers alturd with git, so
`git difftool -t alturd <file>` launches the single-file view built in Plan 04-03.

Purpose: DIFFTOOL-03 is the last requirement of Phase 4 and the one that makes difftool mode
reachable by a real user without hand-editing gitconfig. It is sequenced last because the
`difftool.<name>.cmd` value it writes names the `--difftool-*` flags that 04-03 registers —
writing that string before the flags exist would produce a gitconfig entry that fails when git
evaluates it.

Output: `cmd/alturd/difftool.go` with the subcommand and its gitconfig read/write helpers,
a new `git.ErrLocalScopeOutsideRepo` sentinel, and subprocess integration tests that never
touch the developer's real gitconfig.

This is an expansion plan — the phase's tracer slice landed in 04-01 Task 2.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments → gitconfig key namespace | The `--name` value is interpolated into the config key `difftool.<name>.cmd`. |
| alturd → `git config` subprocess | Keys and values cross a subprocess boundary and are persisted to a file git also reads. |
| gitconfig `cmd` value → shell | Git evaluates the stored `cmd` string in a shell on every later `git difftool -t alturd` invocation. |
| alturd → the user's existing gitconfig | An existing file containing unrelated keys, comments and ordering is modified in place by git. |
